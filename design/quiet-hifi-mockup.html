The rules beneath the screens

Quiet, but never ambiguous.

One accent. A clear hierarchy.

Warm charcoal, soft white and muted green are the default, not a fixed skin. Approved requirement: application colours must use semantic theme tokens for surfaces, text, borders, accent, focus, selection and status. Users can change the palette through Appearance settings, preview it, save it across restarts and restore the default. Custom palettes must be checked for readable contrast; Windows high-contrast mode takes precedence.

Segoe UI for content; monospace for time. Four-pixel corners and 4 / 8 / 12 / 16 / 24 spacing. Character comes from proportion, not decoration. Colour changes must not require layout or playback changes. These static mockups illustrate the default palette only.

States that do not depend on colour alone.

Selected row▶ Currently playingUnavailable · Retry

Selection uses an outline. Playback has an icon and text. Errors have a description and recovery. Keyboard focus must remain visible; native Windows scaling and high-contrast behaviour are implementation requirements.

Approved direction: Quiet Hi-Fi hierarchy, source separation and transport; colours must remain changeable.Not yet specified visually: queue drawer, add dialogs, empty states, Appearance settings and compact layouts.
